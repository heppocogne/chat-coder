# chat-coder

コーディングエージェントが使えない環境で、LLM チャットをエージェント代わりにする半自動ループです。
Windows 専用・Python 標準ライブラリのみで動きます。

## 使い方

```
python -m chat_coder [プロジェクトのルート]
```

(`pip install -e .` すれば `chat-coder` コマンドでも起動できます)

1. 指示を入力し、空行で確定します。
2. プロジェクトが pack され、クリップボードに入ります。
3. チャットに貼り付けて送信し、応答をコピーします(コードブロックのコピーボタンでも全文コピーでも可)。
4. コピーを検知して自動で反映し、変更したファイルの一覧を表示します。
5. そのまま次の指示を入力します。

### チャット画面への自動入力(任意)

`pip install pywinauto`(または `pip install -e .[auto]`)のうえで `--window` にチャット画面の
ウィンドウタイトル(正規表現)を渡すと、pack を作るたびにそのウィンドウを前面に出して入力・送信します。

```
python -m chat_coder --window "ChatGPT" [プロジェクトのルート]
```

- **事前にチャットの入力欄へカーソルを置いておいてください。** ウィンドウを前面に出すだけで、入力欄は探しません。
- 既定はクリップボードを `Ctrl+V` で貼ります。貼り付けで空白が崩れる場合は `--type` で1文字ずつ入力します
  (改行は `Shift+Enter`。遅いので大きい pack には不向き。Tab 文字はブラウザのフォーカス移動になるため使えません)。
- `--no-submit` を付けると入力だけして、送信(`Enter`)は手で行います。
- 失敗したときはメッセージを出し、従来どおり手で貼り付ける運用に戻ります。

### txt ファイルへの書き出し(自動入力が途切れる場合)

pywinauto での入力が途中で途切れる場合は、`--txt` で pack を txt ファイルに書き出します。
自動入力は行わないので、`--window` とは同時に指定できません。

```
python -m chat_coder --txt [プロジェクトのルート]
```

- 既定の書き出し先は `<プロジェクトのルート>/.llm_backup/pack.txt` です(毎回上書き)。
  `--txt 任意のパス` で場所を変えられます。
- 書き出したファイルをチャットに添付して送信してください。クリップボードにも同じ内容が入るので、
  貼り付けで送ることもできます。
- `.llm_backup/` は pack の対象外です。プロジェクト内の別の場所に書き出すと、次の pack に含まれてしまうので注意してください。

### コマンド(指示の代わりに1行だけ入力。空行を待たずに実行されます)

| コマンド | 内容 |
|---|---|
| `/undo` | 直前の反映を元に戻す(何回でも戻せる) |
| `/redo` | `/undo` を取り消す |
| `/copy` | 直前の pack をもう一度クリップボードへ |
| `/q` | 終了(何も入力せず空行でも終了) |

反映後に手でファイルを編集していた場合、`/undo` は上書きを避けて止まります。
上書きしてよければ `/undo!` を使います。

### 応答の検知

pack には「応答の先頭行に `### LLM_LOOP <id>`、最終行に `### END <id>` を書く」というルールが含まれます。
`<id>` は送信ごとに変わる値で、開始と終了で同じ値を書かせます。

- 変更ブロックのない回答(質問への答えだけ)も検知します。説明文はコンソールに表示します。
- 古い応答や、送信した pack 自体をコピーしても反映されません。
- モデルが前回までの id を写して書いてしまった場合(エラーだけを再送したときに起きがち)は、
  このセッションで使った id なら今回の応答として受け付けます。同じ内容の応答を使い回した場合は無視します。
- `### END <id>` がない応答は「途中で切れた」とみなして待機します。チャットで「続き」と送り、
  続きをコピーすると連結して反映します。`Ctrl+C` でここまでを反映するか選べます。
- 完了と判定するのは、id が一致する `### END <id>` の行だけです(複数あれば最後の行)。
  コードや説明の中の単独行 `### END` や、別の id の行では完了扱いになりません。

## 動作の詳細

- pack の対象: プロジェクト内の全ファイルから、次の除外ルールに一致するものを除きます。
  git 管理下かどうかに関わらず同じルールで動きます。
  1. 各ディレクトリの `.gitignore`(`*` `?` `[]` `**` `!` 否定、先頭/末尾の `/` に対応)
  2. ルートの `.llmignore`(このツール専用。`.gitignore` と同じ書式で、**最後に評価される**)

  `.llmignore` が無ければ、起動時に既定の内容(`node_modules/`、`dist/`、ロックファイルなど)で自動作成します。
  編集すれば送信対象を変えられ、`.env` や鍵ファイル用の行もコメントアウトした状態で入っています。
  作成後は、このファイルの内容が既定ルールの代わりになります(行を消せば、その種類のファイルは送られます)。
  `.git/` と `.llm_backup/` だけは、どのルールでも常に除外されます。

  さらに、バイナリ・200KB 超・文字コード不明のファイルは除外し、理由を毎回表示します。
- 文字コード: UTF-8(BOM の有無)と cp932 を扱い、書き込み時も元の文字コード・改行(CRLF)を保ちます。
- 反映: SEARCH/REPLACE 形式。1箇所でも失敗したら何も書き換えず、エラー内容を次の指示に付けます。
  - ブロックは行単位で解釈し、マーカーの記号数(5〜9個)・大文字小文字・インデント、
    `### FILE:` と SEARCH の間の空行やコードフェンス、同じファイルの続きブロックでの `### FILE:` 省略を許容します。
  - エラーは `[形式]`(ブロックの書き方: 該当行・原因つき)と `[適用]`(SEARCH が元コードと食い違う:
    ブロック番号、最も近い箇所の行番号、違っている行の SEARCH/元コード、インデントだけの違い、複数一致の行番号)に分けて表示します。
  - 応答を短くするため、SEARCH は一意になる最小限でよく、長い範囲は
    「先頭の数行 / `...` だけの行 / 末尾の数行」と書けば間を省略できます(間はすべて REPLACE に置き換わります)。
- バックアップ: `.llm_backup/日時/{before,after}/`(`.llm_backup/.gitignore` で git の対象外)。
- 入力中の `Ctrl+C` は入力の取り消しだけで、終了しません。
